# 架构：目录职责与边界

## 顶层结构

```
es-lab/
├── backend/     Java 21 + Spring Boot 3.3.5（唯一与 ES 通信的进程）
├── front/       Vite 6 + React 18 + TypeScript（纯静态产物，无后端逻辑）
├── sh/          全部 shell 脚本——唯一的命令入口
├── docs/        项目文档（本目录）
├── var/         运行期状态（seed.json）
└── logs/        运行日志（spring.log）
```

根目录**没有 `package.json`**：后端是 Java，前端在 `front/` 内有自己的。所有操作走 `sh/` 下的脚本。

## backend/

```
backend/src/main/
├── java/com/eslab/
│   ├── EsLabApplication.java     入口；--seed 时以非 Web 模式运行
│   ├── lib/                      基础设施
│   │   ├── EsClient.java         ★ ES 访问唯一入口
│   │   ├── EsResponse.java       body + status + 耗时
│   │   ├── EsException.java      统一错误（含 root_cause 翻译）
│   │   ├── Timing.java           多轮采样取中位数（丢首轮预热）；pair() 做 A/B 交替采样
│   │   ├── Probe.java            把 ES 原始响应压成 facts 指标
│   │   ├── ProjectRoot.java      定位仓库根（裸跑 mvn 时也能找到 front/dist）
│   │   └── Json.java             Jackson 便捷构造
│   ├── levels/                   54 关，一关一类，类名即关卡 id
│   │   ├── CoreLevels.java       M1-M6 的十个操作型小关卡（CRUD / 巡检 / bulk 失败 / 字段裁剪 / 聚合桶 / scroll / explain）
│   │   └── support/
│   │       ├── LabIndexes.java   ★ 28 个实验索引的唯一登记处（名字/定义/生命周期/归属/目标条数）
│   │       ├── LabData.java      执行器：幂等建库、rebuild、reindex、别名切换；每索引一把锁
│   │       └── LabGate.java      读写锁：关卡运行持读锁，reset/rebuild 持写锁
│   ├── experiments/              4 个 A/B 实验
│   ├── data/                     ★ 数据集唯一实现
│   │   ├── DatasetService.java   v1/v2 定义、bulk 分批写入、状态统计、全部 eslab-* 摘要
│   │   ├── JobRegistry.java      长任务进度表，前端轮询
│   │   └── DataController.java   /api/data 系列接口
│   ├── seed/                     Generator（确定性 PRNG）/ ProductDoc / SeedCommand / SeedService
│   ├── web/                      ApiController / LevelRunner / LabController / LabResetService / WebConfig / ServerPortConfig
│   └── model/                    与前端约定的响应结构
└── resources/knowledge/          modules.json（打进 classpath）
```

**边界规则**

- 只有 `EsClient` 知道 ES 地址与传输细节；关卡代码只写 `es.post("/index/_search", body)`。
- 只有 `DatasetService` 知道「v1/v2 长什么样、怎么写」。页面按钮、第 0 章关卡、`sh/seed.sh` 全走它，三条路径必然一致。
- `LabIndexes` 是**索引事实的唯一来源**：名字、定义、生命周期、归属章节、目标条数都只在这里写一次；`validate()` 在启动时校验，登记不全直接让 Spring 起不来。
- `LabData` 只管执行：`ensure` / `rebuild` / `reindexAsync` / `swapAlias`，不再持有任何定义。写方法会二次校验索引名，绝不碰 `eslab-products-*`。
- `LevelRunner` 负责「跑一关」这件事本身：先按 `aliasBaselines()` 归位别名，再持 `LabGate` 读锁执行 `run()` —— 别名与复位不会和运行中的关卡打架。
- M1-M6 的十个操作型小关卡集中在 `CoreLevels`：它们不引入新原理，只把「一类日常操作」做完整（含对照与失败分支）。每关先 rebuild `eslab-goods-core`，所以重复运行不累积副作用。
- 关卡源码即教学内容：`@focus-start/@focus-end` 标出供前端高亮的行区间。
- `application.yml` 用独立前缀 `eslab.*`，避免被环境变量（如 `SERVER__PORT`）宽松绑定污染。

**边界规则**

- 前端不直连 ES，一切经 `/api/*`。
- 前端不硬编码教学文案，全部来自 `/api/knowledge`。
- 源码抽屉显示的是**后端 Java 源码**，不是前端代码。
- 路由用 hash（`#/level/m0-2`）而非 history API：静态产物由 Spring Boot 托管，刷新 `/level/x` 会 404。
- `lib/levelCalls.ts` 是唯一一处前端硬编码的技术清单：关卡的请求序列在 `run()` 内部发生，后端只回结果，页面要「跑之前就看见命令」只能自己写一份。改 `levels/*.java` 的请求时同步改它，路径必须与实际发出的完全一致。

## sh/

| 脚本 | 职责 |
|---|---|
| `_common.sh` | 公共函数：导出 `ESLAB_ROOT`、端口探测、颜色输出 |
| `backend.sh` | 启动后端（8787） |
| `front.sh` | 启动 vite dev server（5173，`/api` 代理到 8787） |
| `dev.sh` | 同时起后端 + 前端 |
| `build.sh` | 后端 compile + 前端 build |
| `seed.sh` | **快进**：跳过第 0 章，直接预置全量数据 |
| `stop.sh` | 停掉本项目启动的进程 |
| `clean.sh` | 分档清理（`--es` / `--data` / `--build`），默认 dry-run |

ES 只删 `eslab-*` 前缀；文件只删 `var/`、`logs/`、`front/dist`、`backend/target`；不碰 `elastic-stack` 与 `node_modules`。

## var/ 与 logs/

- `var/seed.json`：种子元数据（文档数、时间、模式），m7-2 据此取数据规模。
- `logs/spring.log`：后端输出。
- 两者都可再生，删除不影响功能。

## ES 访问层

依赖官方 `co.elastic.clients:elasticsearch-java:8.18.5`（与服务端同版本），但 `EsClient` 只用其中的**低层 `RestClient`**，不用高层强类型 API：

1. **教学可见性**：关卡代码是 `method + path + JSON body`，读源码即可对应 curl；换成 lambda DSL 后「请求长什么样」会被 SDK 掩盖。
2. **统一 API**：`call()` 返回 `JsonNode`，44 关 / 4 实验 / seed 只依赖这一层。
3. **错误语义**：4xx/5xx 抛 `ResponseException`，`EsClient` 转成 `EsException`（带 root_cause 人话翻译）。

实现细节：

- 超时只能在 `RestClient.builder` 的 `RequestConfig` 上设（`RequestOptions` 不支持），因此按超时档位缓存实例（`Map<Integer, RestClient>`）。
- HEAD / 204 无实体，读 body 前判空。
- 不读系统代理环境变量，`127.0.0.1` 直连。

未来若要换强类型 API，只需替换 `EsClient` 一个类。

## 课程与数据

```
第 0 章（页面） ──┐
数据工坊按钮  ──┼──▶ DatasetService ──▶ ES
sh/seed.sh    ──┘        同一个实现
```

第 0 章带学员从空集群建索引、写文档、灌 2 万；`seed.sh` 是「快进」，跳过第 0 章直接预置全量。

前置条件由 `modules.json` 的 `prereq` 声明（哪个索引、至少多少文档），前端 `checkPrereq()` 据此渲染缺口清单与修复按钮，未满足时禁用「运行本关」。

## 内容模型：deep 为什么是块数组

`knowledge/modules.json` 里每关的 `deep` 是一个 `DeepBlock[]`，不是一段字符串：

| 块 | 用途 |
|---|---|
| `p` / `h` / `ul` / `ol` | 正文与分节；`h` 同时生成阅读页目录锚点 |
| `code` | 请求体与 DSL，等宽块，不计入字数 |
| `table` | 对照表（三种模式、四个子句、参数清单） |
| `callout` | 提示框：warn / info / insight 三种语气 |
| `compare` | 左右对照卡（object vs nested、GET vs _search） |
| `figure` | 引用一张 SVG 原理图 + 图注 |

渲染只有一处：`components/deep/DeepDoc.tsx` 做 switch；行内只支持反引号代码与双星号加粗（`Inline.tsx`）。
这样做的原因很直接：表格、对照与图无法用纯文本表达，而引入 markdown 解析器等于自己实现一门小语言。
