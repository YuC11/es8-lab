# 环境限制

本机实测确认的边界，不是待办。写下来避免重复踩坑。

## 1. ES 必须手动启动

自动化环境启动 ES 会失败：`sandbox_init(): Operation not permitted` —— ES 8.x 内置沙箱与宿主沙箱冲突，无法关闭。**因此本项目不含任何 ES 启动脚本。**

```bash
# 前台
/Users/yc/environment/elastic-stack/elasticsearch-8.18.5/bin/elasticsearch

# 后台
/Users/yc/environment/elastic-stack/elasticsearch-8.18.5/bin/elasticsearch -d -p /tmp/es.pid
kill $(cat /tmp/es.pid)
```

## 2. 不使用容器

用本地 `/Users/yc/environment/elastic-stack` 的 ES：8.18.5 单节点、`my-es-cluster`、`xpack.security.enabled: false`、已装 `analysis-ik`。

## 3. 代理会劫持 localhost

本机 shell 曾出现 `HTTP_PROXY=127.0.0.1:57381`，导致 127.0.0.1 的请求被吞（`upstream connect failed`）。

- 手工 curl 一律加 `--noproxy '*'`
- Java 侧：`RestClient` 不读代理环境变量，直连，天然规避

## 4. Spring Boot 宽松绑定的端口污染

IDE 注入的 `SERVER__PORT=57355` 会被宽松绑定映射成 `server.port`，顶掉 8787。对策：`ServerPortConfig` 用独立前缀 `eslab.port` 显式 setPort。

## 5. 集群 yellow 与本项目无关

`yellow` 来自既有索引（`articles`、`test_aggs` 等 replica=1 且单节点无法分配），`eslab-*` 自身是 green。本项目只读连接集群，不改任何全局配置。
