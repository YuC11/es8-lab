## 质量门槛

剩余每一关的「完成」按以下六条验收，**不以正文长度作质量指标**：

1. **问题与假设**：目标是可验证问题，运行前有预测，但不评分。
2. **基线与对照**：明确只改哪个变量，数据集、查询、规模、刷新状态保持一致。
3. **分步动作**：运行前状态、核心请求、对照请求、清理/恢复；破坏性步骤写明影响范围。
4. **证据**：返回原始 ES 响应并从中提取可核对指标；性能结论用多轮中位数，非性能结论给命中、mapping、计数或错误响应等结构证据。
5. **解释边界**：写出本机单节点/小数据的局限、混淆变量和不可外推的结论。
6. **迁移练习**：至少一条 probe 只改一个参数；有可逆状态的关卡必须附复位方式。

完成定义：`objective / predict / steps / takeaway / pitfall / probes` 与源码一致；`levelCalls.ts` 的请求与真实执行顺序一致；页面能展示关键原始证据；清理后重跑可复现。实现遵守架构边界：ES 请求只走 `EsClient`，v1/v2 只由 `DatasetService` 管，实验索引用 `LabData` 且限于 `eslab-*`。

## 索引边界（改动时必须遵守）

- 本轮仍**不变更 `eslab-products-v1/v2` 主索引**。需要写入、删除、改 mapping 的演示一律落在可重建的 `eslab-goods-*`。
- 特殊类型（nested 数组关联、geo、dense_vector）另建 `eslab-goods-nested-*` / `geo-*` / `vector-*`，不塞进主索引。
- 有生命周期或破坏性的状态（模板、pipeline、同义词、rollover、删除/冲突演示）继续用独立实验资源，并定义 cleanup / re-run。
