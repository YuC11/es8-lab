# 索引治理

54 关跑完一遍，集群里会留下 20 多个 `eslab-*` 索引、几十万条文档。在引入注册表之前，这些索引的**四个事实分散在四个地方**：

| 事实 | 原来在哪 | 后果 |
| --- | --- | --- |
| 名字 | `LabData` 常量 + 5 个关卡类里的字面量 | 同一个字段表被抄 3 遍，改一处漏两处 |
| 定义 | `DatasetService` / `LabData` / 各关卡 `run()` 内联 | 谁都能改，改完不知道影响哪些关 |
| 生命周期 | 藏在各关的 `recreate()` / `delete()` 调用里 | 只能靠读代码才知道「这个索引跑完会不会留下」 |
| 归属 | `modules.json` 的 `prereq` | 索引和关卡是两张皮，前置检查会误判 |

这份文档描述治理之后的结构。

## 一、一处登记：`levels/support/LabIndexes.java`

```java
public record IndexSpec(
        String name,                       // 索引名
        String chapter,                    // 归属章节（m0…m11）
        String ownerLevel,                 // 归属关卡 id
        Lifecycle lifecycle,               // 谁在什么时候该删
        ResetCost resetCost,               // 重建代价：秒 / 十几秒 / 分钟
        Source source,                     // 数据从哪来
        int targetDocs,                    // 多少条算达标
        Supplier<Map<String, Object>> definition,
        List<String> aliases,
        boolean labWritable,
        String note) { … }
```

三条约束：

1. **定义只在这里派生**。`v3` 之后的定义一律 `copy(ds.v2Definition())`，不复制字段表 —— 否则 v2 改一个字段，v3 到 v6 就跟不上。
2. **每个索引必须能回答四件事**：谁建的、什么生命周期、多少条算达标、属哪一章。
3. **启动即校验**。`validate()` 检查名字前缀、目标条数、reindex 源、别名目标是否登记；任何一条不成立直接让 Spring 起不来 —— 这类错误在运行时只表现为「某一关 404」，越早炸越好。

`LabData` 退化为**执行器**：`ensure` / `rebuild` / `reindexAsync` / `swapAlias`。它不再持有任何定义。

## 三、六种生命周期

| 值 | 含义 | 面板标签 |
| --- | --- | --- |
| `PERSISTENT` | 建一次就复用，条数不符才重建 | 常驻 |
| `RESET_ON_RUN` | 每次运行先清空再灌 | 每轮重置 |
| `RECREATE_ON_RUN` | 每次运行删掉重建，由关卡自己灌 | 每轮重建 |
| `DROP_AFTER_RUN` | 关卡结束就删，异常路径也删 | 跑完即删 |
| `ROLLOVER` | 滚动族，写别名指向其中一个 | 滚动族 |
| `PLANNED` | 只 `_simulate`，永不创建 | 仅模拟 |

生命周期不是装饰：前端「实验索引」面板的标签直接来自这几个值，`/api/lab/reset` 的删除范围也按它算。

## 四、幂等与并发

三个曾经真实存在、现在已修掉的缺陷：

### 1. 「补差额」补成了「重搬一遍」

```java
// 旧：判定 have < target 之后，reindex 搬的是 target 条，不是差额
if (have < LabData.DOCS) lab.reindex(SOURCE, V4, LabData.DOCS, null);
// 目标已有 5,000 条 → 变成 25,000 条
```

现在**改为重建**：条数不等于目标就 `delete → put → reindex → 校验`，前后保存并重挂别名。
重建比补差额贵，但只有一种结果状态，不会累积。

### 2. `count()` 失败被当成 0

```java
// 旧：读失败返回 -1，调用处 Math.max(0, count) 变成 0 → 重新灌满 → 重复文档
long have = Math.max(0, lab.count(name));
```

现在分成两个方法：写路径用 `count()`（失败直接抛异常），只读展示用 `countQuietly()`（返回 -1）。
**代码里不再有 `Math.max(0, count)`**。

### 3. 重建与填充在锁外的两个临界区

`recreate()` 只在自己的 delete+PUT 期间持锁，调用方在锁外灌数据 —— 两个关卡并发跑
`core` / `ops` 会互相清空。现在合成一个原子方法：

```java
public Ensure rebuild(String name, Filler filler)   // 清空 + 填充，全程持该索引的锁
```

每个索引一把 `ReentrantLock`，`delete` 也加锁。另外 `LabGate` 提供一把读写锁：
关卡运行持读锁、`/api/lab/reset` 与 rebuild 持写锁 —— 复位不会撞上进行中的关卡。

`sh/seed.sh` 另起 JVM 写 v1/v2，进程内的锁管不到它，所以脚本**先探测 8787**：
后端在跑就直接退出并提示，避免两个写入方同时操作同一索引。

## 五、别名归位

`eslab-goods` 是全局可变状态，曾经谁跑谁改：

| 关卡 | 旧行为 |
| --- | --- |
| m8-1 | 只在别名不存在时才挂 v3 |
| m8-2 | 无条件切 v4 |
| m9-6 | 无条件切 v6 |

结果依赖执行顺序；`m9-6` 表格里写死的「切换前指向 v4」，从 m8-1 直接跳过去时是假的（实际是 v3）。

现在每个关卡**声明自己的基线**，由 `LevelRunner` 在 `run()` 之前统一归位：

```java
// M82ZeroDowntime
@Override
public List<AliasBaseline> aliasBaselines() {
    return List.of(new AliasBaseline(LabIndexes.ALIAS, LabIndexes.V3));
}
```

归位是幂等操作：先 `ensure(target)` 保证目标索引在，再 `swapAlias`。结果与执行顺序无关，
表格里写的「切换前」读的是运行时的真实值，不是常量。

## 六、复位与重建

| 方式 | 作用范围 | 用法 |
| --- | --- | --- |
| 前端「实验索引」面板 | 只看，不改 | 路线图首屏，折叠展开 |
| `POST /api/lab/reset` | 按索引 / 章节 / 家族 / 全部删除 | `dryRun` 默认 `true` |
| `POST /api/lab/rebuild` | 把索引重建到基线条数 | 同上 |
| `sh/clean.sh` | 删索引 + 模板 + pipeline + 本地文件 | 默认 dry-run，`--yes` 才真删 |

`/api/lab/reset` 只接受**注册表里的名字**：传 `*`、传 `eslab-products-*`、传任何未登记的名字一律 `400`。
这条比控制台白名单更严 —— 白名单拦的是单条请求，这里是批量删除。

`clean.sh` 与它分工：脚本管「本地文件 + 集群资产」，接口管「运行期的索引」。两者都会删
`eslab-goods-template` 与 `eslab-goods-enrich`，这是之前漏掉的两个。

## 七、从零开始

```bash
sh sh/clean.sh --yes            # 删全部 eslab-*、模板、pipeline、本地产物
sh sh/backend.sh                # 起后端
curl -X POST localhost:8787/api/lab/rebuild \
     -H 'Content-Type: application/json' \
     -d '{"scope":"baseline","dryRun":false}'   # v1/v2 灌到 2 万
```

然后按课程顺序跑 54 关即可。每章的索引条数应等于它的 `targetDocs`，可以在
`/api/lab/indexes` 里逐条核对。

## 八、冷启动回归（2026-11-06 实测）

「清理后可复现」这条只有真跑一遍才知道。流程：

```bash
sh sh/clean.sh --yes --all --with-services     # 删索引 + 资产 + 构建产物
sh sh/build.sh                                  # 从零构建
sh sh/backend.sh                                # 起后端
POST /api/lab/rebuild {"scope":"baseline"}      # v1/v2 各 2 万条（实测 5.9s）
# 按课程顺序跑 54 关，每章跑完核对条数
```

### 54 关结果

**54/54 通过，43 秒**，0 失败。九次章后核对里八次 OK，唯一一处差异是：

```

```

这不是偏差：m0-3 会往 v1 写一条样例文档再看 refresh 行为，m0-4 再 bulk 灌 2 万 ——
`20000 + 1` 才是这一章的正确终态。

### 逆序别名测试

按 `m9-6 → m8-2 → m8-1 → m9-6` 跑，每一步的「切换前」都是运行时真实值：

| 步骤 | 别名进入时的指向 | 本关归位到 | 表格里写的「切换前」 |
| --- | --- | --- | --- |
| m9-6（第一次） | v6 | v4 | v4，命中 0 |
| m8-2 | v4 | v3 | v3，命中 20,000 |
| m8-1 | v4 | v3（再切 v4、复原 v3） | 四个阶段逐行记录 |
| m9-6（第二次） | v3 | v4 | v4，命中 0 |

m8-1 的表格完整走了「归位前 v4 → 归位到 v3 → 切到 v4 → 复原 v3」，`/api/levels/m9-6/run`
返回的 `aliasPins` 也明确写出 `{"from":"eslab-goods-v3","to":"eslab-goods-v4","changed":true}`。
**两次 m9-6 之间别名被 m8-1 改过，结论仍然是「切换前 0 条」** —— 这就是归位的意义。

### 两轮六关比对

同一批六关，在「已有数据」与「clean + rebuild 之后」各跑一次：

| 关卡 | 第一轮 | 第二轮 | 判定 |
| --- | --- | --- | --- |
| m8-1 | 20,000 / 20,000 / 2 个动作 / 收尾 v3 | 同 | 一致 |
| m8-2 | 20,000 / 2 个 / 20,000 → 20,000 | 同 | 一致 |
| m8-3 | 20,000 / 100 条失败 / 已取消 / 20,000 | 同 | 一致 |
| m8-4 | 段数 **3 → 3** | 段数 **5 → 3** | 差异已解释（见下） |
| m9-1 | 15.89 / 18.21 / 11.69 | 15.84 / 18.35 / 11.68 | 差异已解释（见下） |
| m9-6 | 5 个词项 / 0 → 1,301 / 2 个动作 | 同 | 一致 |

两处差异都不是「不稳定」，而是两种正常的初始状态：

- **m8-4 的段数**：第一轮的 v3 已经被合并过，所以是 `3 → 3`（幂等）；第二轮 v3 是新建的，`5 → 3`
  （首次合并）。这正是关卡要教的「重复执行不改变结果」。
- **m9-1 的分数**：课程数据用自动 `_id`，重建后 `_id` 变了 → 文档落到不同分片 →
  每个分片各自的 `avgFieldLength` 不同 → BM25 分数浮动约 0.3%。
  **排序结论（哪种模式分高、加 `tie_breaker` 后 most_fields 是否退化）不受影响。**

### 这轮回归修掉的三个缺陷

| 缺陷 | 表现 | 修法 |
| --- | --- | --- |
| `clean.sh` 用 `xargs -P` 并发删除 | macOS 的 BSD xargs 报 `command line cannot be assembled, too long`，**13 个索引一个都没删掉**，脚本仍打印「清理完成」 | 改串行 for 循环；`failed` 计数也顺带从子 shell 里解放出来 |
| `/api/lab/rebuild` 忽略 `dryRun` | 传 `dryRun: true` 仍**真的删了重建**，v1/v2 各灌 2 万条 | 计划与执行分离：先算 `plan`，dryRun 只返回 `wouldRebuild` |
| 8 个 `eslab-demo-*` 登记成「每轮重建」 | 面板显示「未建」却没有解释，让人以为索引丢了 | 改成 `DROP_AFTER_RUN`，面板标签变「跑完即删」 |

前两条都属于「脚本说成功、实际没做」或「标记为预览、实际写入」，是比数字错更难发现的类型。

## 九、已知边界

- **锁是进程内的**。多实例部署时 `LabData` 的锁不起作用，需要换成集群级锁。
- **`max_docs` 与 `slices>1` 一起用会少搬**（ES 8.18.5 实测：20,000 条配 `slices=2` 只搬 16,667）。
  所以 `reindexAsync` 在 `maxDocs <= 0` 时不写 `max_docs`，想要精确条数就别设上限。
- **`docs: -1` 表示「不存在或读取失败」**，不是 0。前端已经按这个语义处理，脚本里也不要当 0 用。
- **`eslab-products-*` 不计入 reset 的默认范围**：它们要重灌 20 万条，属于 `ResetCost.SLOW`，
  必须显式传 `includeProducts: true`。
